# ObsLite: Efficient Agent Training with Selective Observation Masking

English | [简体中文](README_zh.md)

**ObsLite** reduces repeated input during agent training by selectively masking older environment observations.

We study ObsLite in WebShop, first fine-tuning Qwen3.5-0.8B on 1,418 teacher trajectories generated by Qwen3.5-27B, then applying observation masking during GRPO training and evaluation. ObsLite retains the initial observation, the current observation and its four immediate predecessors, and error feedback containing `Invalid action!` or `Invalid format.`. Other older observations are replaced with short placeholders, while all historical Thought and Action messages are preserved. Compared with full-history GRPO, ObsLite increases success rate from 41.2% to 41.6%, reduces average total tokens by approximately 36.8%, and shortens training time by approximately 20.6%.

## Results

Experiments use a single NVIDIA RTX 6000D GPU with 84 GB of memory. We evaluate ObsLite both as an inference-time context policy for the SFT model and as part of GRPO training and evaluation.

### Comparison on the SFT model

We fine-tune Qwen3.5-0.8B with QLoRA on 1,418 teacher trajectories generated by Qwen3.5-27B. All three variants below share the same SFT model and differ only in their evaluation context. The two-step O/A window retains the previous two Observation/Action pairs and the current Observation.

ObsLite achieves the highest success rate and mean reward, improving success from 35.8% with full history to 38.2% while reducing average total tokens by approximately 41.1%. The two-step O/A window uses fewer tokens but lowers success to 29.8%.

| Method | Success rate | Mean reward | Mean interactions | Avg. total tokens |
| --- | ---: | ---: | ---: | ---: |
| Qwen3.5-0.8B | 7.8% | 0.13218 | 16.578 | 139,606 |
| SFT, full history | 35.8% | 0.58315 | 8.172 | 47,791 |
| SFT + ObsLite | **38.2%** | **0.60425** | **7.830** | 28,155 |
| SFT, two-step O/A window | 29.8% | 0.48698 | 10.210 | **17,443** |

### ObsLite during GRPO training

Both runs start from the same SFT model and use LoRA for 20 rounds of GRPO training. We use vLLM to generate interaction trajectories, sampling eight per task with up to 32 sequences generated concurrently.

The GRPO baseline uses full history, whereas ObsLite retains only selected past observations throughout training to shorten the model's context. ObsLite achieves a slightly higher success rate of 41.6%, compared with 41.2% for full history, along with a slightly higher mean reward. Average total tokens decrease by approximately 36.8%, and training time decreases by approximately 20.6%.

| Method | Success rate | Mean reward | Mean interactions | Avg. total tokens | RL training time (hours) |
| --- | ---: | ---: | ---: | ---: | ---: |
| GRPO | 41.2% | 0.62943 | 7.700 | 40,485 | 14.78 |
| ObsLite + GRPO | **41.6%** | **0.63695** | **7.542** | **25,571** | **11.74** |

See the [20-round training-time table](results/TRAINING_TIME.md) for per-round timings and [results/episodes](results/episodes) for per-task and per-step records.

## Engineering optimizations

We use the following optimizations to reduce training and runtime overhead:

| Optimization | Purpose |
|---|---|
| Input padding trimming | Remove leading padding before computation while preserving all valid content. |
| On-demand logits | Compute vocabulary scores only where needed to score the generated Thought and Action tokens, reducing compute and memory use. |
| FLA kernels | Accelerate Qwen3.5's Gated DeltaNet computation with FLA, using FP32 for the actor and reference models. |
| Product data caching | Cache cleaned WebShop product data to avoid repeated preprocessing. |

At the same FP32 precision, FLA reduces the time spent on model forward and backward computation by approximately 71–80%.

## Installation

On a Linux server with an NVIDIA driver, Conda, and Git installed, run:

```bash
bash setup.sh
```

The script installs dependencies, downloads verl-agent and the WebShop environment packaged by ETO, and automatically downloads and extracts the product catalog and search index.

## Training

Download the Qwen3.5-0.8B model weights separately. SFT teacher trajectories and training tasks are included in the repository, and the setup script prepares the WebShop data.

The commands below assume the base model is stored in `models/Qwen3.5-0.8B`. Replace this with your actual path.

**Step 1: SFT.** Train the base model on the teacher trajectories and export it to `models/sft-export`:

```bash
bash run.sh sft models/Qwen3.5-0.8B
```

**Step 2: ObsLite GRPO.** Starting from the SFT model trained above, apply selective observation masking throughout GRPO training for 20 rounds, saving a checkpoint every two rounds:

```bash
bash run.sh train models/Qwen3.5-0.8B
```

Before training, the program automatically checks FP32/FLA computations using teacher data. Training begins once the check passes, and checkpoints are saved under `runs/mask4-grpo20/checkpoints/`.

## Evaluation

Evaluate the round-20 model as an example:

```bash
# Model saved after 20 training rounds
MODEL=runs/mask4-grpo20/checkpoints/global_step_20/actor/lora_adapter

# Evaluate 500 tasks and save results to runs/eval-obslite
bash run.sh evaluate "$MODEL" runs/eval-obslite
```
